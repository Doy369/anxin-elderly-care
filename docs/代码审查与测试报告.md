## 一、测试方法

没有用真机点，而是**用内存数据库模拟 `wx-server-sdk`，直接调用云函数的 `exports.main`**，按真实业务流程跑。

`scripts/test-cloud.js` 里实现了一个迷你云端：

- 支持 `collection / add / where / doc / orderBy / limit / get / update / remove / count`
- 支持 `db.command` 的 `in / and / or / eq`
- 通过 `Module._load` 拦截 `require('wx-server-sdk')`，不改动业务代码

这样能在本地验证**状态机、权限、并发**这些真机很难复现的东西——尤其是两个人同时接单。

跑法：

```bash
node scripts/test-cloud.js     # 云函数功能测试（39 项）
node scripts/check-refs.js     # 工程结构自检
node scripts/test-store.js     # 数据层单测（19 项）
```

## 三、发现并已修复的问题

### P0-1 · 状态流转存在权限旁路

`transition` 里原本是：

```js
if (!DEMO_MODE && user.role !== 'staff' && user.role !== 'admin') {
  return { ok: false, message: '无权执行该操作' }
}
```

`DEMO_MODE` 为 true 时，**任何登录用户只要传 `actor: 'staff'`，就能把任意订单推进到任意允许状态**——包括把别人的单改成「已接单」占住。

改成必须校验真实师傅身份，且已接单的订单只认接单本人：

```js
const staff = await getStaff(user)
if (!staff) return { ok: false, message: '无权执行该操作' }
if (order.staffId && order.staffId !== staff._id) {
  return { ok: false, message: '这单不是您接的' }
}
```

同时删掉了 `DEMO_MODE` 常量（已无引用），`utils/config.js` 的 `demoMode` 置为 `false`。**副作用：订单详情的「模拟机构推进」按钮不再显示**，全流程需两个账号配合测试。

### P0-2 · 评价功能缺失，订单会永久卡在「待评价」

状态机里 `待评价 → 已完成` 只允许用户操作，但**页面上没有任何评价入口**。之前全靠 `demoMode` 的演示按钮，一旦关掉，订单就死在这一步。

新增云函数 `rate` action + 订单详情页的评价卡：五星选择、200 字评论、提交后写入 `rating / comment / ratedAt` 并流转到「已完成」，同时记一条日志。评分做了 1–5 的夹取。

### P0-3 · 订单详情里的师傅信息是硬编码假数据

```js
content: '陈师傅\n138 0000 0000\n服务时间 8:00 - 20:00'
```

所有订单都显示同一个「陈师傅」。改为接单时把 `staffPhone` 一起写入订单，详情页按实际订单显示；没有师傅或没有电话时给出对应提示。

## 五、遗留风险

- **师傅激活码 `AXIN2026` 硬编码在云函数里**，任何人拿到源码就能认证成师傅接单。上线前必须换成随机串。
- **没有评价的内容审核**。用户可填任意文字，小程序有内容安全要求，正式上线前应接 `security.msgSecCheck`。
- **没有订阅消息**，用户不知道师傅什么时候到，只能自己反复看订单。
- **云存储权限**目前是「所有用户可读」，手机号打码了但照片没有，理论上拿到 fileID 就能看。可接受，但要知道。
