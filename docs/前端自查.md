## P0 · 会影响使用

### 1. 次要文字对比度不达标，且是大面积使用

这是最严重的一条。我在 `docs/可行框架v1.md` 里把「对比度 ≥4.5:1」写成了硬性要求，新配色自己没达标。

| 用途 | 色值 | 实测对比度 | 判定 |
|---|---|---|---|
| 主文字 | `#1F2D22` | 14.42:1 | 达标 |
| 正文 | `#3D4A3F` | 9.33:1 | 达标 |
| 次文字 | `#6B7B6E` | 4.48:1 | 临界（差 0.02） |
| **辅助说明** | `#8A9A8C` | **2.97:1** | 不达标 |
| **更弱文字** | `#9AAA9C` | **2.44:1** | 不达标 |
| **输入占位** | `#B0BEB2` | **1.93:1** | 不达标 |
| 心情提示 | `#7CB07F` | 2.51:1 | 不达标 |
| 主绿按钮白字 | 白 / `#43A047` | 3.30:1 | 仅够大字（≥3:1） |

受影响的位置很多：`section-sub`、`room-desc`、`tip-desc`、`topic-desc`、`head-sub`、`row-desc`、`quick-desc`、`oc-time`、输入框 placeholder。

对老人来说，这些正是"看不清就跳过"的那部分字。设计稿原图也是浅灰，但设计稿是给视觉看的，真机在强光、老花眼条件下会明显吃亏。

**建议**：把 `#8A9A8C` → `#6B7B6E`（4.48:1，勉强）、更稳的是 `#5F7165`（约 5.6:1）；`#9AAA9C` → `#6B7B6E`；占位符 `#B0BEB2` → `#8A9A8C`（占位符可以放宽到 3:1）。主按钮绿加深到 `#3D9142`（白字约 4.1:1）。

### 2. 订单金额恒显示 ¥0

新预约表单没有计价字段，`booking.js` 提交时 `amount: 0`。云端照存，订单详情照显：

```html
<text class="info-value amount">¥{{order.amount}}（{{order.quantity}}{{order.unit}}）</text>
```

→ 显示「¥0（1次）」。服务类订单本来就没有固定价（要上门评估），显示 0 元会让用户以为免费。

**建议**：`amount > 0` 才渲染这一行，否则显示「费用面议」或「上门评估后报价」。

### 3. 从房间预约改造，丢失房间信息

`myhome.js` 跳转时带了房间名：

```js
wx.navigateTo({ url: '/pages/booking/booking?service=repair&from=' + encodeURIComponent(room.name) })
```

但 `booking.js` 的 `onLoad` 只读了 `options.service`，`from` 完全没用。结果：从「浴室」点预约改造，进去是通用的「维修服务」表单，师傅拿到订单也不知道是哪个房间。

**建议**：读 `options.from`，写进备注前缀，或在表单顶部显示「改造房间：浴室」。

## P1 · 体验缺陷

### 4. 「我的」页年龄写死

```js
meta: '70岁 · 150****8888'
...
meta: user.phone ? ('70岁 · ' + user.phone) : FALLBACK.meta
```

真实用户有手机号也会被写成 70 岁。资料编辑功能没做，这里全是占位。

### 5. 心语页「健康小知识」是死链

4 条内容点了都只弹「内容正在整理中」。列表看着完整，实际没有一个能打开——比不展示更伤。

### 6. 两处占位功能

「我的收藏」→ toast「开发中」；「资料编辑」→ toast「开发中」。

### 7. 「待接单」状态徽标几乎看不见

`orders.wxss` 里 `.status-pending { background: #F6FAF5; }`，白卡片上等于没底色，只剩文字。批量换色时把原来的浅黄底映射成了浅绿底，而浅绿底又和卡片同色了。

### 8. 自定义 tabBar 的 emoji 灰度可能不生效（待真机确认）

用 `filter: grayscale(100%)` + `opacity: .45` 把未选中图标压暗。部分 iOS 及低版本基础库对彩色 emoji 应用 filter 的效果不一致，可能出现「未选中仍是彩色」。

**建议**：真机看一眼；不稳的话改成给未选中项加半透明白色遮罩，或直接换图标图片。

## P2 · 技术债

### 9. 两个后端的 `updateOrder` 语义不一致

- `local-store.updateOrder`：整体替换 `records` 数组
- `cloud-api.updateOrder`：只取数组最后一条，走 `addRecord` 追加

当前调用方式（传入「原数组 + 新记录」）两边结果相同，但语义不同。将来若有人传完整数组做修改，本地会覆盖、云端会追加。

### 10. 演示开关仍是开的

`utils/config.js` 的 `demoMode: true`、`cloudfunctions/order/index.js` 的 `DEMO_MODE = true`。
上线前必须都改 `false`，否则下单人能自己把订单推到「已完成」。

### 11. 房间与服务用 emoji 占位

设计稿是实拍照，我拿不到素材。替换点：`myhome.wxml` 的 `.room-photo` 块（改成 `<image>` 即可，布局不用动）；服务图标在 `help.wxml` 的 `.help-icon`。
