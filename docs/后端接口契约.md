# 自建后端接口契约

前端已经把数据层抽象成三个实现（`cloud-api` / `http-store` / `local-store`），
切后端只需改 `utils/config.js` 的 `BACKEND`，页面代码一行不动。

这份文档是给后端同学看的：**照这个契约实现，前端不用改。**

---

## 一、通用约定

| 项 | 约定 |
|---|---|
| 请求方式 | 全部 `POST {apiBase}/{模块}` |
| 模块 | `auth` / `order` / `home` / `room` / `elder` / `staff` / `upload` |
| 请求体 | JSON，含 `action` 字段区分操作，其余参数字段见各模块 |
| 成功响应 | `{ "ok": true, ...其他字段 }`，HTTP 200 |
| 业务失败 | `{ "ok": false, "message": "给用户看的中文提示" }`，HTTP 200 |
| 鉴权失败 | HTTP 401，前端会清除本地 token 并提示重新登录 |
| 无权限 | HTTP 403 |
| 服务端错误 | HTTP 5xx，前端统一提示「服务异常，请稍后重试」 |

**为什么是 action 分发而不是 REST**：现有 5 个云函数就是 `switch (event.action)` 的结构，
服务端照抄 switch 分支即可，逻辑迁移风险最小。以后可以再改 RESTful。

---

## 二、登录

`POST /auth`  `{ "action": "login", "code": "<wx.login 拿到的 code>" }`

```json
{ "ok": true, "token": "自定义 token", "user": { "id": "u_1", "nickname": "张奶奶" } }
```

服务端要做：用 `code` 调微信 `code2session` 换 `openid`，建或查用户，签发自己的 token。
**AppSecret 只能放服务端**，绝不能进小程序包。

## 三、订单 `POST /order`

| action | 入参 | 返回 |
|---|---|---|
| `list` | `{ filter?: 'ongoing' \| 'done' }` | `{ ok, list: [order] }` |
| `detail` | `{ id }` | `{ ok, order, logs }` |
| `create` | `{ order: {...} }` | `{ ok, order }` |
| `transition` | `{ id, to, note?, actor? }` | `{ ok, order }` |
| `addRecord` | `{ id, content, worker }` | `{ ok, order }` |
| `remove` | `{ id }` | `{ ok }` |
| `rate` | `{ id, rating, comment }` | `{ ok, rating }` |
| `pool` | 无 | `{ ok, list }` |
| `mine` | 无 | `{ ok, list }` |
| `accept` | `{ id }` | `{ ok }` |
| `arrive` | `{ id }` | `{ ok }` |
| `finish` | `{ id, media: [fileID], note }` | `{ ok }` |

### 订单字段（camelCase）

```
id, orderNo, userId, homeId, roomType, elderId,
serviceId, serviceName, icon, provider, unit, price, quantity, amount,
forWhom, contactName, phone, address, date, timeSlot, remark, bookedBy,
status, records[], media[],
staffId, staffName, staffPhone, staffUserId,
acceptedAt, arrivedAt, finishedAt,
rating, comment, ratedAt,
createdAt, updatedAt
```

### 状态机（必须原样实现）

```
待接单   → 已接单[staff] / 已拒单[staff] / 已取消[user]
已接单   → 服务中[staff] / 已取消[user]
服务中   → 待评价[staff]
待评价   → 已完成[user]
已完成   → 售后中[user]
已拒单   → 待接单[staff]
```

每次流转必须写一条 `order_logs`：`{ orderId, fromStatus, toStatus, operatorId, operatorRole, note, createdAt }`。

### 三个不能改的实现细节

1. **接单必须用条件更新做乐观锁**
   ```sql
   UPDATE orders SET status='已接单', staff_id=?, accepted_at=?
   WHERE id=? AND status='待接单';
   -- affectedRows === 0 → 返回 { ok:false, message:'手慢了，这单已被接走' }
   ```
   严禁先 `SELECT` 判断再 `UPDATE`。

2. **`pool` 返回的手机号必须打码**：`138****1111`。完整号码只在 `accept` 之后通过 `detail` 返回。

3. **可见性判定**：下单人本人 / 可访问的老人档案 / 可访问的房屋，三者之一。
   已接单的师傅可以看自己那单，且只能看状态为「待接单」的单（用于接单前评估，同样打码）。

## 四、房屋 `POST /home`

| action | 入参 | 返回 |
|---|---|---|
| `list` | 无 | `{ ok, list: [home] }`，首次调用若无房屋要自动建一套「我的家」 |
| `create` | `{ data: { name, address, area, floor, elevator, remark } }` | `{ ok, home }` |
| `update` | `{ homeId, data }` | `{ ok, home }` |
| `remove` | `{ homeId }` | `{ ok }` |

限制：一人最多 5 套；只有 `owner` 能删除；有进行中订单时拒绝删除。

权限表 `home_access`：`{ homeId, userId, role: 'owner'|'member', status }`。

---

## 五、房间资产 `POST /room`

| action | 入参 | 返回 |
|---|---|---|
| `list` | `{ homeId }` | `{ ok, assets: { [roomType]: { fileID, checks[], photoUpdatedAt } } }` |
| `savePhoto` | `{ homeId, roomType, fileID }` | `{ ok }` |
| `removePhoto` | `{ homeId, roomType }` | `{ ok }` |
| `setChecks` | `{ homeId, roomType, checks: [下标] }` | `{ ok }` |

`roomType` 取值：`living / bedroom / kitchen / bathroom / entry / balcony`。

**只读规则**：房屋成员可读写；已接该房屋订单的师傅只读（只允许 `list`）。

## 六、家人档案 `POST /elder`

| action | 入参 |
|---|---|
| `list` | 无 |
| `create` | `{ data: member }` |
| `update` | `{ id, data }` |
| `remove` | `{ id }` |

权限走 `elder_bindings`：`{ elder_id, user_id, relation, status }`。

---

## 七、服务人员 `POST /staff`

| action | 入参 | 返回 |
|---|---|---|
| `me` | 无 | `{ ok, role, staff }`，未认证时 `staff: null` |
| `activate` | `{ data: { code, name, phone } }` | `{ ok, staff }` |

## 八、文件上传 `POST /upload`（multipart）

字段：`file`（文件）、`folder`（如 `homes/h_1`）、`name`（如 `bathroom`）

```json
{ "ok": true, "fileID": "https://cdn.example.com/..." }
```

`fileID` 会被直接塞进 `<image src>`，所以要么是可公网访问的 URL，
要么是前端能换取临时地址的标识（此时需另加一个取图接口，并同步改前端）。

**签名必须服务端下发**，accessKey 不能进小程序。

---

## 九、切换步骤

1. 后端按上面实现，部署到 HTTPS 域名并完成备案
2. 小程序后台 → 开发管理 → 服务器域名 → 把域名加进 `request` 和 `uploadFile` 合法域名
3. `utils/config.js` 改两行：
   ```js
   const BACKEND = 'http'
   const API_BASE = 'https://api.your-domain.com'
   ```
4. 重新编译，跑一遍 `node scripts/test-http.js` 和真机冒烟

前端不需要改任何页面。

---

## 十、数据迁移

如果云端已经跑了真实数据，切换前要导出：

```bash
# 云开发控制台 → 数据库 → 每个集合 → 导出 JSON
```

需要迁的集合：`users / homes / home_access / elders / elder_bindings / orders / order_logs / room_assets / staff`。

注意 `_id` 是字符串，导入新库时建议保持字符串主键（UUID 或雪花），
否则前端拼接 URL 的地方要做类型兼容。
