# 交付与部署说明

给接手这份代码的人看。照着走一遍，从零到能跑通全流程大约 40 分钟（不含云开发环境创建和审核等待）。

---

## 一、交接清单

**要交付**
- 完整代码仓库（含 7 个云函数）
- 本文件

**不要交付**
- 云数据库导出的 JSON（里面是真实用户数据）
- AppSecret（`code2session` 用，只存在于服务端）
- 任何 `.env`、密钥文件

代码里目前有两处硬编码凭证，交接前让对方改掉，见第五节。

---

## 二、五分钟跑起来（最短路径）

```bash
# 1. 克隆
git clone <仓库地址> anxin
cd anxin

# 2. 改两处配置
#    project.config.json → "appid": "你的 AppID"
#    utils/config.js     → CLOUD_ENV = '你的云开发环境ID'

# 3. 用微信开发者工具导入该目录

# 4. 部署云函数（CLI，或工具里右键逐个「上传并部署：云端安装依赖」）
```

云函数一共 7 个，全靠 CLI 批量部署：

```bash
cli cloud functions deploy \
  --env <你的环境ID> \
  --names login home elder order room staff init \
  --project <项目路径> \
  --remote-npm-install
```

> 首次部署新函数时可能报 `当前函数处于Creating状态`，等 15 秒重试即可。

**5. 建集合**：云开发控制台 → 云函数 → `init` → 测试，入参：

```json
{ "key": "AXIN-INIT-2026", "action": "schema" }
```

九个集合一次建好，重复调用不会报错。

**6. 建索引**：入参 `{"key":"AXIN-INIT-2026","action":"indexes"}` 会返回完整清单，照第三节的表格在控制台点。

**7. 设权限**：九个集合逐个改「仅管理端可读写」。

**8. 生成演示数据**：小程序先编译一次、进一次首页（触发登录），然后在调试器 Console 里执行：

```js
wx.cloud.callFunction({
  name: 'init',
  data: { key: 'AXIN-INIT-2026', action: 'demo' }
}).then(console.log)
```

会为当前用户建 1 套房屋、3 间房的自查记录、2 个家人档案、2 条示例订单。刷新页面就能看到内容。

## 三、索引清单（14 个）

| 集合 | 索引名 | 字段（按顺序） | 唯一 |
|---|---|---|---|
| `users` | `uniq_openid` | `openid` | **是** |
| `elder_bindings` | `idx_user_status` | `user_id` → `status` | 否 |
| `elder_bindings` | `idx_elder_id` | `elder_id` | 否 |
| `orders` | `idx_user_id` | `userId` | 否 |
| `orders` | `idx_elder_created` | `elderId` → `createdAt`（降序） | 否 |
| `orders` | `idx_status` | `status` | 否 |
| `orders` | `idx_home_created` | `homeId` → `createdAt`（降序） | 否 |
| `orders` | `idx_staff_accepted` | `staffId` → `acceptedAt`（降序） | 否 |
| `order_logs` | `idx_order_id` | `orderId` | 否 |
| `homes` | `idx_owner` | `ownerUserId` | 否 |
| `home_access` | `idx_user_status` | `userId` → `status` | 否 |
| `home_access` | `uniq_home_user` | `homeId` → `userId` | **是** |
| `room_assets` | `uniq_home_room` | `homeId` → `roomType` | **是** |
| `staff` | `idx_user_status` | `userId` → `status` | 否 |

三个唯一索引不能省：

- `uniq_openid`：否则同一个微信可能被建出两条用户记录
- `uniq_home_user`：否则同一人对同一套房会重复授权
- `uniq_home_room`：否则一间房可能出现两条资产记录，照片互相覆盖

组合索引的字段顺序不能反，`createdAt` / `acceptedAt` 选降序。

## 四、集合权限

九个集合全部设为「**仅管理端可读写**」。

所有读写都经过云函数，云函数以管理员身份操作，不受集合权限限制。设成「所有用户可读」的话，任何拿到 AppID 的人都能直接拉全表。

## 五、交接前必须改的三处

### 1. 师傅激活码

`cloudfunctions/staff/index.js`

```js
const STAFF_CODE = 'AXIN2026'   // 改成一串随机字符
```

不改的话，知道这个码的人都能认证成师傅接单，看到工单池里的客户地址。

### 2. 初始化口令

`cloudfunctions/init/index.js`

```js
const INIT_KEY = 'AXIN-INIT-2026'
```

### 3. 上线前删除 init 云函数

`init` 能建集合、能灌数据，留在生产环境是个后门。正式发布前：

```bash
# 控制台删除，或
cli cloud functions delete --env <环境ID> --names init
```

至少也要把 `INIT_KEY` 改成只有你知道的串。

## 六、部署后自检

```bash
node scripts/check-refs.js    # 结构完整性、require 路径、事件绑定、三方接口一致性
node scripts/test-cloud.js    # 39 项业务流程（内存数据库，不连云端）
node scripts/test-store.js    # 19 项本地数据层
node scripts/test-http.js     # 10 项自建后端适配层
```

真机冒烟顺序：

1. 首页能加载，无「数据初始化中」
2. 我的家 → 点客厅 → 上传一张照片 → 返回看缩略图
3. 帮我一下 → 选服务 → 三步表单 → 提交
4. 我的 → 我的订单 → 能看到刚提交的单
5. 我的 → 服务人员入口 → 输入激活码认证
6. 工单池能看到刚才那单 → 接单 → 打卡 → 完成（要传图）
7. 回订单详情 → 评价 → 已完成

## 七、常见问题

**「数据初始化中，请退出小程序重新进入」**
集合没建。跑一遍 `init` 的 `schema`。

**「服务未部署，请稍后重试」**
云函数没传上去，或传了但没勾「云端安装依赖」。

**工单池空着**
不是所有订单都进池子，只有状态为「待接单」的。另外接单前手机号是打码的，这是设计如此。

**师傅接单后看不到房屋照片**
业主没上传过照片；或者师傅手上没有该房屋的订单（权限按「已接单」判定）。

**照片上传失败**
云开发没启用，或云存储权限不对。默认「所有用户可读，仅创建者可写」即可。

## 八、技术栈与依赖

| 项 | 说明 |
|---|---|
| 框架 | 原生微信小程序，**无 npm 依赖**，不需要「构建 npm」 |
| 后端 | 微信云开发（云函数 + 云数据库 + 云存储） |
| 数据层 | 可切三种后端：`cloud` / `http` / `local`，改 `utils/config.js` 一个常量 |
| 自建后端 | 接口契约见 `docs/后端接口契约.md`，27 个 action |
| 测试 | 四个脚本，共 68 项断言，不连云端也能跑 |

如果对方不想用云开发，按 `docs/后端接口契约.md` 实现一套 HTTP 接口，
把 `config.js` 的 `BACKEND` 改成 `'http'`、填上 `API_BASE` 即可，页面代码不用动。
