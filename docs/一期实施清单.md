## 前置：确认 AppID 与云开发

`project.config.json` 里已经是真实 AppID `wx4bfdeaa9cbd67a9b`，云开发这条路是通的。

**测试号（touristappid）不支持云开发**，必须是注册过的小程序。

### 第 1 步：开通云开发

1. 微信开发者工具打开本项目
2. 点顶部工具栏「云开发」
3. 首次会提示开通，选择「按量付费」或「基础版」，创建环境
4. 环境创建后，在「设置 → 环境设置」里复制 **环境 ID**（形如 `anxin-prod-8gk2xxxxxx`）

### 第 2 步：填环境 ID

打开 `utils/config.js`，把环境 ID 填进去：

```js
const CLOUD_ENV = 'anxin-prod-8gk2xxxxxx'
```

保存即生效。`useCloud` 会自动变成 `true`，数据层切到云端。没填时自动走本地，不会报错。

### 第 3 步：建数据库集合

云开发控制台 → 数据库 → 新建集合，建这 5 个：

| 集合 | 存什么 |
|---|---|
| `users` | 微信用户，openid、角色 |
| `elders` | 老人档案（数据主体） |
| `elder_bindings` | 账号与档案的绑定关系、权限 |
| `orders` | 订单 |
| `order_logs` | 状态流转日志，每次变更一条 |

**权限设置**：每个集合都改成「**仅管理端可读写**」。

原因：小程序端不直接读写数据库，全部通过云函数。云函数有管理端权限，不受这条限制。这样能防止别人绕过云函数直接改数据。

### 第 4 步：建索引

云开发控制台 → 数据库 → 选中集合 → 索引管理：

| 集合 | 字段 | 类型 |
|---|---|---|
| `users` | `openid` | 唯一 |
| `elder_bindings` | `user_id` + `status` | 组合 |
| `elder_bindings` | `elder_id` | 普通 |
| `orders` | `userId` | 普通 |
| `orders` | `elderId` + `createdAt` | 组合，createdAt 降序 |
| `orders` | `status` | 普通 |
| `order_logs` | `orderId` | 普通 |

不做索引也能跑，数据过了几百条会明显变慢。

### 第 5 步：上传云函数

开发者工具左侧目录树，右键 `cloudfunctions` 下的每个函数：

- `login`
- `elder`
- `order`

依次选「**上传并部署：云端安装依赖**」。三个都要传，缺一个对应功能就报错。

上传后在云开发控制台 → 云函数里能看到，状态「正常」。

## 验证清单

按顺序走一遍，每步都该通过：

| # | 操作 | 预期 |
|---|---|---|
| 1 | 首次进入小程序 | 控制台无报错；云开发控制台 `users` 集合多一条记录 |
| 2 | 「我的 → 家人档案 → 添加」 | 保存成功；`elders` 和 `elder_bindings` 各多一条 |
| 3 | 下单 | `orders` 多一条，状态「待接单」；`order_logs` 多一条「下单」日志 |
| 4 | 订单详情 | 时间线停在「待接单」 |
| 5 | 点「模拟机构推进到下一步」 | 状态变「已接单」，`order_logs` 多一条，操作者记为 staff |
| 6 | 连点 4 次 | 依次到 已接单 → 服务中 → 待评价 → 已完成 |
| 7 | 已完成后再点 | 按钮消失（状态机不允许） |
| 8 | 换一台设备/换一个微信号进入 | **看不到别人的订单**（数据隔离生效） |
| 9 | 把 `config.js` 的环境 ID 清空重编译 | 自动退回本地模式，功能仍可用 |

第 8 条最关键——如果能看到别人的订单，说明云函数里的权限校验没生效，必须排查后再继续。

## 两个上线前必须改的地方

### 1. 关掉演示模式

`utils/config.js`：

```js
demoMode: false
```

`cloudfunctions/order/index.js`：

```js
const DEMO_MODE = false
```

不关的话，下单人自己就能把订单推到「已完成」，等于没有履约管控。

### 2. 接机构端之前，状态只能人工改

一期没有机构端，订单会停在「待接单」。演示模式关掉后，只能由你在云开发控制台手动改 `orders.status`——但这**不会写 `order_logs`**，会留下审计缺口。

正式运营前必须把机构端的接单功能做出来。

## 常见错误

| 报错 | 原因 | 处理 |
|---|---|---|
| `wx.cloud is not defined` | 基础库过低或未开通云开发 | 调高调试基础库版本，确认环境已创建 |
| `cloud function not found` | 函数没上传 | 右键对应目录「上传并部署」 |
| `Cannot find module 'wx-server-sdk'` | 用了「上传」而不是「上传并部署：云端安装依赖」 | 重新上传，选云端安装依赖 |
| `database permission denied` | 集合权限设成了「仅创建者可读写」 | 改成「仅管理端可读写」 |
| 登录成功但列表为空 | 索引没建，或绑定时 `status` 字段不对 | 检查 `elder_bindings` 里 `status` 是否为 `active` |
